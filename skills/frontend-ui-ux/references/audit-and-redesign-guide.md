# 既有系统设计审计与重构升级指南 (Audit & Redesign)

## 1. 重构审计工作流 (Scan → Diagnose → Upgrade)

重构既有系统时，严禁盲目直接全部推倒重写。遵循以下三部曲：
1. **代码扫描 (Scan)**：识别既有技术栈（Tailwind v3/v4、CSS Modules、Vanilla）、核心路由结构与业务状态流。
2. **坏味道诊断 (Diagnose)**：对照本文第 2 节逐项排查 AI 坏味道与结构性缺陷。
3. **分层升级 (Upgrade)**：遵循低风险、高收益的杠杆序列逐步落地。

---

## 2. 360 度设计坏味道排查清单 (Audit Checklist)

### 2.1 排版与文字坏味道
- [ ] **默认字体泛滥**：使用系统 Arial/Roboto 或千篇一律的 Inter，缺乏品牌个性。
- [ ] **字阶行高失控**：大标题桌面端超过 3 行，段落文本单行字符数超过 75 字符。
- [ ] **破折号残存**：全文字面出现 `—` 或 `–`（必须彻底清除）。
- [ ] **数据无等宽**：在财务、监控数据面板中使用比例字体导致数字抖动（应使用 `font-mono` 或 `tabular-nums`）。

### 2.2 色彩与表面坏味道
- [ ] **纯黑背景**：使用死板的 `#000000`（应替换为 Zinc-950 / `#0A0A0A`）。
- [ ] **AI 紫色泛光**：无意义的荧光紫/荧光蓝径向大渐变与发光边框。
- [ ] **多重高亮冲突**：页面同时出现绿、蓝、橙、紫等多种主动作颜色（应收敛为 1 主色 + 1 点睛色）。
- [ ] **中途黑白翻转**：在亮色主题页面中间突兀插播一个深黑 Section（造成视觉割裂）。

### 2.3 布局与容器坏味道
- [ ] **盒子嵌套地狱**：卡片套卡片套卡片 (`cards-inside-cards-inside-cards`)。
- [ ] **三等分卡片重复**：从头到尾连续使用 3 列等宽卡片。
- [ ] **视口高度灾难**：英雄区使用 `h-screen` 导致移动端 Safari 底部栏弹缩跳动（必须使用 `min-h-[100dvh]`）。
- [ ] **Bento 留白漏洞**：CSS Grid 未声明 `grid-flow-dense`，导致网格中间留有丑陋空洞。

### 2.4 交互与状态坏味道
- [ ] **交互零反馈**：按钮无 Active 态物理微下压或微缩放。
- [ ] **无障碍丢失**：缺少键盘聚焦轮廓 (`focus-visible:ring-2`)，或按钮白底白字对比度不足。
- [ ] **状态机缺失**：缺少骨架屏 Loading、空数据 Empty State、表单行内报错。

## 3. 现代化重构升级优先级杠杆 (Lever Priority)

按以下顺序实施升级，可在最小破坏业务逻辑的前提下获得最大的视觉品质飞跃：

```
[优先级 1] 字体与排版重塑 (Font & Type Scale) ──► 替换个性化 Sans/Serif，压实标题行距
     │
[优先级 2] 调色盘收敛 (Palette Cleanup) ──────► 剔除高饱和杂色，锁定单一品牌色，优化对比度
     │
[优先级 3] 呼吸感与微布局 (Whitespace & Grid) ─► 扩大垂直间距 (py-24+)，引入非对称与 Bento
     │
[优先级 4] 交互微质感注入 (Tactile States) ────► 按钮内嵌图标、双层倒角、Hover/Active 弹簧物理
     │
[优先级 5] 页面级动效升维 (Choreography) ──────► 接入 GSAP 吸顶堆叠或 Motion 入场级联
     │
[优先级 6] 状态机补全 (Edge States) ───────────► 骨架屏、空状态与清晰报错引导
```

---

## 4. 严禁静默修改的防御红线 (Preservation Invariants)

在进行视觉重构时，严禁在未获明确授权下修改以下内容：
1. **SEO 与路由路径**：URL 路由结构、页面 Slug、Canonical 链接。
2. **核心业务文案与法律声明**：隐私政策、服务条款、合规说明。
3. **数据埋点标识**：HTML 中供数据埋点与自动化测试识别的 `data-testid`、核心 ID 及表单 name 属性。
