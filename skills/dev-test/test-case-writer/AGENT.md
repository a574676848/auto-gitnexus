# Test Case Writer

用于生成测试用例，不默认改代码。

## 流程

1. 使用 `test-governance-core` 的标准流程收集上下文。
2. 先确认真实环境、真实账号、真实服务、真实测试数据和数据边界；缺少任一必要信息时，**暂停用例生成，主动向用户追问缺失项，等用户补齐后立即继续生成**，不得只输出清单后退出。
3. 识别项目类型、主业务入口、已有测试和文档依据。
4. 从代码、README、docs、API、路由、CLI 帮助、知识库和 bug/需求中提取可验证行为。
5. 若用户提供用例，逐条映射源码、接口/页面/CLI、配置、数据模型、文档依据、已有测试和待确认项，并据此确定测试范围与排除范围。
6. 对跨服务或多项目用例，列出涉及项目、服务调用链、上游入口、下游依赖、数据流、认证/租户边界和各项目测试入口。
7. 按 QA/QC 视角明确真实环境、真实测试数据、验收标准、关键断言、质量风险和放行判断；用户已澄清的信息应直接复用并写入用例前置条件，源澄清记录仍必须落在被测项目 `test-governance/reports/clarifications.md` 或本次报告同目录小节。
8. 按 P0/P1/P2 分层生成用例。
9. 标记每条用例的建议自动化方式：unit / integration / ui / smoke / manual。
10. 输出时使用 core 的 `references/report-template.md` 中的测试用例格式。
11. 默认增量维护 `test-governance/test-cases.md`：只新增或更新相关用例，除非用户明确要求全量重建。

## 约束

- 不编造不存在的页面、接口、命令或账号。
- 没有证据的场景只能标记为“待确认”，不能写成已知事实。
- 优先覆盖主流场景，不追求 100%。
- 如果用户要求落盘，默认写入 `test-governance/test-cases.md`；长期对外文档再同步到 `docs/TEST_CASES.md`。
