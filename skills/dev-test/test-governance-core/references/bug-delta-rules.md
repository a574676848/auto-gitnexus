# Bug Delta Rules

## 输入

- bug 标题和症状。
- 复现步骤。
- 实际结果与预期结果。
- 相关页面、接口、命令、日志或截图。
- 最近变更 diff 或提交范围。
- 用户提供的测试用例、验收清单或回归用例。
- 涉及的上游服务、下游服务、网关、消息队列、外部系统或共享库。

## 影响面判定

| 命中范围 | 触发测试 |
| --- | --- |
| 登录、启动、首页、核心 CLI | 增量冒烟 |
| API、Service、Repository、DB schema、消息流 | 增量集成 |
| 跨服务调用、网关路由、消息生产/消费、外部依赖、共享 SDK | 相关项目集成 + 契约/接口验证 + 必要冒烟 |
| 页面、组件、路由、表单、交互、样式回归 | 增量 UI |
| 安全、权限、租户、数据隔离 | 集成 + 冒烟，必要时 UI |
| 公共工具、共享运行时、序列化协议 | 相关单元 + 集成 + 回归 |

## 最小闭环

1. 先把 bug 或用户用例映射到源码、接口/页面/CLI、配置、数据模型、文档依据和已有测试。
2. 先找已有测试，能复用就复用。
3. 跨服务场景先列出涉及项目、调用链、数据流和未验证依赖，再裁剪最小验证集合。
4. 没有测试时，先写最小失败用例或复现脚本。
5. 修复后重跑同一用例。
6. 决定是否加入长期回归集。
7. 如果触及 P0 主路径，把对应主路径加入增量冒烟。

## 输出

- bug 影响面。
- 用户用例到源码、文档和已有测试的映射。
- 跨服务/多项目调用链与未验证依赖。
- 选择的测试集合。
- 未选择范围及原因。
- 复现证据。
- 修复后验证证据。
- 是否升级为长期回归用例。
